# React and TypeScript for the game

The game is about 40 hand-written ES modules with no framework and no bundler, and its views draw themselves by assigning template strings to `innerHTML` (about 120 places), so cross-site scripting is a class of bug the code invites, and cleanup depends on every author remembering `js/life.js`. We move the game at `/play/` to React 19 with the React Compiler, TypeScript `strict` and **React Router v7 in framework mode, rendered on the server in a Cloudflare Worker** (React Router's Vite plugin with the Cloudflare Vite plugin), step by step: the router mounts a Legacy view or a React view per route, and each pull request moves a few views with the Playwright suite green. Static files are served first by Workers static assets and never run code; the Worker renders only game paths that have no file. Pages that are the same for every visitor (the Sutra pages, the Guide, the first-visit Mode picker) are prerendered at build time. Game paths are paths under `/play/`; old `#/` links become paths through a pre-paint shim, forever. Player data stays on the device: the server renders only what is the same for every visitor, routes have no server loaders, and parts that depend on Player data render in the browser. Server-rendered pages allow their inline scripts with a per-request nonce; static pages keep hashes. Game, math and storage logic stays framework-free TypeScript (`shared/` for code the server also uses, `app/src/logic/` for the rest), read by React through one `useStore(selector)` hook on `useSyncExternalStore`. Content stored as HTML text renders only through one allow-list `Markup` component, and `dangerouslySetInnerHTML` is banned everywhere else. Styles stay plain CSS on the design-system tokens, one file per component. The service worker stays hand-written (`sw.ts`), its precache list made from the client build's manifest, with a build-rendered offline shell. One repo with pnpm workspaces: `app/`, `workers/`, `shared/`. All server code is TypeScript on Cloudflare: Workers, Durable Objects for live rooms, R2 for voice files.

Status: accepted 2026-10-19 (proposed 2026-10-17) in the `react-typescript` change (owner decisions 1 to 13; every open question answered 2026-10-19, including path URLs, Q18). Revised 2026-10-20 (owner decisions N1 and N2, "yes"): React Router framework mode with server rendering on Cloudflare Workers replaces the first form of this record (a Vite single-page app with React Router in SPA mode, build-time prerendering only, "the site stays static assets"). Implementation started once the `learnvedicmath` move was live. Supersedes "no framework, no bundler, no TypeScript in the browser" wherever it is stated: the option "TypeScript in the browser app too" that ADR 0010 rejected, `openspec/config.yaml`, the `learnvedicmath` design and `render-performance` (re-planned before it is built). Supersedes, for `/play/` paths with no file, ADR 0004's "static assets only" (the hosting choice itself stands). Numbered after `gpu-effects` (0011). See also ADR 0013 (3D, browser only) and ADR 0014 (server voice).

## Considered Options

- **React Router v7 framework mode with server rendering on Workers (chosen):** one route table for server and browser, server rendering of any game path, build-time prerendering for public pages, nonces for the CSP, and a first-party Cloudflare path (React Router's Cloudflare template and the Cloudflare Vite plugin), so no adapter sits between the framework and the runtime.
- **React Router v7 in SPA mode with a Vite single-page app** (the first form of this record): no server rendering, a fallback file answered by a Worker miss handler, hashes only. Superseded 2026-10-20 once the game gained server code anyway (Duels, Live sessions, the voice endpoint).
- **Next.js on Cloudflare through the OpenNext adapter (`@opennextjs/cloudflare`):** the most used React framework, but built for Vercel. The adapter follows each Next.js release weeks later and lists unsupported features per version; image optimization, ISR, middleware behavior and parts of Partial Prerendering depend on Vercel's platform and need adapter-specific replacements on Cloudflare; the adapter adds its own build step, config and cache bindings to the deploy, and the server bundle sits near the Worker size limit. Server components and server actions would be a second mental model for a game whose data lives on the device.
- **Next.js or anything else on Vercel:** Vercel Hobby forbids commercial use (ADR 0004), and a second vendor would split the site from its Durable Objects and R2 (owner N1: no Vercel).
- **TanStack Start:** good types, but younger, with less settled Cloudflare support.
- **Stay on vanilla modules with JSDoc and `checkJs`** (ADR 0010's choice for the browser): no build step, but no component model, so `innerHTML` stays the way to draw and the XSS class stays.
- **Preact, Solid, Svelte or Lit:** smaller runtimes, but fewer people know them, and React Three Fiber (ADR 0013) is React only.
- **A big-bang rewrite on a branch:** months of drift against content and feature work, and one unreviewable merge.
- **Redux or Zustand for state:** a second state model next to localStorage, which the store already owns.
- **Tailwind or CSS-in-JS:** a second design vocabulary, or `style-src 'unsafe-inline'` against the move's stricter policy.
- **Workbox for the worker:** replaces a short, tested worker with configuration and a runtime.

## Consequences

- Nothing a Player sees or stores changes, except path URLs in `/play/` (old `#/` links are sent to their paths by a pre-paint shim, forever), a redone Star Quest layout on phones, and, for Players with WebGL and motion allowed, a Sky that fades from 2D into 3D (ADR 0013).
- A cold load of any game path is answered with a server-rendered page (shell and server-safe parts) instead of a fallback file; static files, prerendered pages and every client-side navigation run no Worker code, and routes have no server loaders, so navigation works offline.
- The Worker is no longer only a CSP report endpoint, so the site moves to Workers Paid ($5 a month) before server rendering reaches production (owner, 2026-10-20; the Free plan's 10 ms CPU per request is too tight for a React render), as ADR 0004 foresaw.
- Responses the Worker renders carry the whole security header set themselves (`_headers` does not apply to them), with a per-request nonce; the policy text has one source for both.
- `build.py` stops writing the import map and `?v=` stamps; Vite's hashed file names replace them. The move's post-build steps (`_headers`, CSP hashes for static pages, `_redirects`, checks) stay.
- `js/life.js` and the lifecycle scan retire when the last Legacy view moves; an ESLint rule bans bare listeners and timers in components, another bans reading Player data or browser globals during a render, and `dangerouslySetInnerHTML` is banned everywhere. Content stored as HTML text is shown only through one allow-list `Markup` component.
- React, React DOM and React Router add about 70 KB gzip to the client; CI fails any regression in first load (read from the client manifest) or interaction time against the pre-migration baseline, which is measured before the server-rendered shell ships. Every size budget measures Brotli. The Worker bundle has its own size check.
- Feature pull requests pause only for the views being moved; each migration pull request names the views it locks.
- `placement`, `age-bands`, `render-performance`, `duel-online`, Live sessions (a new change) and `gpu-effects` are built after this, in that order, in React, and are re-planned first. `duel-online` keeps its approved rules and moves to `workers/`, `shared/` and TypeScript on a Durable Object room engine that Live sessions reuse.
