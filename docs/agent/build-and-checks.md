# Build, checks and hook

Detail behind the rules in `AGENTS.md` and `CODING_STANDARDS.md`.

- Hosting (ADR 0004): Cloudflare Workers static assets (`wrangler.jsonc`), deployed by CI from `main`. Until the move's owner setup is done, the old app at https://sbmadhav.com/vedic-math/ keeps serving from this repo's GitHub Pages; `--target moved` builds its Phase B replacement (Targets).
- Stamps (the cache stamps rule is in `AGENTS.md`; the worker's `VERSION`, `PRECACHE` and `LAZY` sit between the precache markers). `python3 build.py --out _site` copies the publishable files and stamps the copies: the import map pinning every module to `?v=<hash>`, `?v=` on every same-origin script and stylesheet of every page, the `#vm-css` map for the play stylesheets, the worker's `VERSION`, its precache list (the core) and its `LAZY` list (the stamped URLs saved on first request: `docs/agent/offline.md`). The worker is published as `/sw.js` from `app/src/sw/sw.ts` with its types taken out by `tools/build-sw.mjs` (Node's own type stripper, so the build needs Node 22.13 or newer and no install; every line keeps its place, so the marker lines publish exactly as before). The build fails if the source carries stamps.
- TypeScript the Legacy views import (react-typescript tasks 3.1 to 3.3): a `js/` module that moved to `shared/src/` or `app/src/` keeps its URL and re-exports the `.ts` file. Until the framework build (task 2.1) bundles the game, `build.py` publishes every `.ts` module reachable from `js/` at `/js/ts/<path>.js` with its types taken out (`tools/build-ts.mjs`, the same stripper as the worker), rewrites the `.ts` imports to those URLs and pins them in the import map like any module. Only plain type syntax is allowed in those files (no enums, namespaces or parameter properties), never a dynamic `import()` of a `.ts` file, and never a test; ESLint's `lvm/legacy-imports` allows a `js/` import of `/shared/src/**/*.ts` and `/app/src/**/*.ts` for the same reason.
- Pages: `play/index.html` (the game) and every `site/**/*.html` (landing, grown-up pages, `404.html`, later `/import/`). Each holds the header from `theme/header.html` (`docs/agent/design-system.md`). `<!-- include-md: PATH -->` renders a Markdown file into a page (the legal pages, `/licenses/` from `THIRD-PARTY-NOTICES.md`), without its title, its drafting note or any section headed "(remove before publishing)".
- `_headers` (written by the build): the security headers on `/*`; per page path a `Content-Security-Policy` (that page's inline script hashes plus `THIRD_PARTIES`), a stricter `Content-Security-Policy-Report-Only` and COOP, so no page carries a policy `<meta>`; and `Cache-Control: public, max-age=31536000, immutable` on the folders every page loads at `?v=<content hash>` (`/js/*`, `/css/*`, `/ds/*`, `/theme/*`, `/math.css`; `immutable` in `shared/src/policy.json`, openspec change `render-performance` design D3), never on a page, `sw.js`, a font, an icon or the manifest, whose URLs stay the same across deploys (`e2e/tests/loading.spec.ts`). Never put a policy or COOP on `/*`: Cloudflare joins every matching rule, and two policies are both enforced. The build fails on more than 100 rules or a line over 2,000 characters (then move an inline script out of the page).
- Trick pages (openspec change `trick-pages`; GLOSSARY "Trick page"): `site/tricks/index.html` and the 15 `site/tricks/<slug>/index.html` are generated, never edited by hand: `tools/trick-pages/pages.ts` holds the rows (slug, worked example, description) and the renderers, `pnpm gen:tricks` (`tools/trick-pages/generate.ts`) writes them from `shared/src/vedic.ts` and `theme/header.html`, and `test/trick-pages.test.mjs` fails when a committed page is stale (a change to a Trick's words is committed with the pages it changes). Their calculator is `tools/trick-pages/calculator.ts`: the build publishes every runtime `.ts` in that folder (not `generate.ts`, `pages.ts`, a `.d.ts` or a test) at `/tricks/<name>.js` with its types taken out (`tools/build-ts.mjs`) and its `.ts` imports rewritten like a `js/` module's; it is not under `/js/`, so it is in no game import map, precache or first-load set. Every page outside the game that loads modules gets a page-local import map (compact, before its first module script, hashed into its policy) pinning the static module graph of its module scripts to `?v=<hash>`: the Trick pages, and the landing page's sky modules. The folder's own `tsconfig.json` (DOM types; `/js/*` imports resolve to `tools/trick-pages/types/js/*.d.ts`) runs in the `tools` package's `typecheck`. Each Trick page has a byte budget of its own: `node tools/budget.ts _site --page /tricks/<slug>/` (the page, what it links, its modules' static imports; no worker) against `trickPage.max` in `docs/perf/baseline.json`, which the build checks in every voice mode; `trickPage.changes` records why it moved. `schema.org` (their JSON-LD vocabulary) is in `LINKS`.
- `THIRD_PARTIES` in `build.py` (read from `shared/src/policy.json`, with the policy's directives and the headers on every response, so the Worker can send the same policy; react-typescript task 3.1) is the one list of outside hosts a page or worker may reach, with why and when; `LINKS` lists hosts that are only linked or cited. The build fails on any other host in a published file (vendored files and licence texts aside), on any `/vedic-math/` path outside `_redirects`, on any sbmadhav.com reference other than the export page, and on `gstatic.com/firebasejs`.
- Legal pages: `site/privacy/`, `site/privacy/retention/` and `site/terms/` include `docs/legal/*.md` with `<!-- include-md: -->`; the draft's title, its `> **DRAFT` note and any section headed "... (remove before publishing)" are left out. The build fails on text in `[square brackets]` a reader would see on any page (a draft's placeholder): reword it or move it to the draft's "Open items (remove before publishing)" list.
- Vendored files: `vendor/design-system/2.2.0/`, `vendor/firebase/<v>/` (`tools/vendor-firebase.mjs`), `vendor/goatcounter/` each have a `SHA256SUMS` the build and `test/vendor.test.mjs` check. Every file under `vendor/` or `fonts/` needs an entry in `THIRD-PARTY-NOTICES.md`. The published `/ds/2.2.0/tokens.css` drops its `@font-face` lines; `theme/fonts.css` declares the fonts once.
- Targets: `--dev` (no stamps, `'dev'` worker, into `_dev/`), `--preview` (adds `X-Robots-Tag: noindex, nofollow`), `--target moved` (the Phase B page for sbmadhav.com/vedic-math/, into `_moved/`: `moved/index.html` as `index.html` and `404.html`, the packer and schema pinned, `sw.js` with `KILL = true` and the old `vedic-math-` prefix), `--voice static` (Workers Paid file limit), `--voice off` (no Studio voice: the voice host is left out of the policy and `sw.js`, the published `js/voice-index.js` names no recording, and the build fails if any published file names the voice host; CI builds this way while `vars.R2_ACCOUNT_ID` is empty). `BUILD_TODAY=YYYY-MM-DD` fakes the date for the security.txt expiry check. `--out DIR` puts the build anywhere outside the repo, or inside it only when its first path part below the repo root starts with `_` (`_site`, `_check/site`; `build/_site` is refused because `build` does not; the default outputs do; a worktree build is `--out _<name>`): git and ESLint ignore `_*/` (`.gitignore`, `eslint.config.js`), the build never publishes a path starting with `_`, and `build.py` refuses the repo itself and any other place inside it (`test/build.test.mjs` checks both).
- Limits (Cloudflare Workers Free): 20,000 files, 25 MiB a file; `/.well-known/security.txt` must expire more than 30 days ahead and less than a year ahead.
- The published files are every file git knows about minus `exclude` in `_config.yml` and any path with a part starting with `.` or `_` (so thumbnails are `thumbs/yt-<id>.webp`). The build also writes `_redirects`, `robots.txt`, `sitemap.xml`, `.well-known/security.txt` and `.assetsignore`.
- Workspaces (openspec change react-typescript, phase 1): pnpm, pinned by `packageManager` in `package.json` (`corepack enable`, then `pnpm install`), with the packages `app/` (the service worker source today; the React Router app from phase 2), `shared/`, `workers/` (the Worker: `src/index.ts` routes `/_csp` to `src/csp.ts`; the second Worker, `learnvedicmath-ledger` in `workers/ledger/wrangler.jsonc`, entry `src/ledger-worker.ts`, holds the VoiceLedger Durable Object, which the main Worker binds by `script_name`: Cloudflare generates no preview URL for a Worker that implements a Durable Object, so no Durable Object class may go in the main Worker), `e2e/` and `tools/`. `tsconfig.base.json` holds the strict settings every package extends. `tools/voice`, `tools/sutra-voice`, `cloud/test` and `deploy/` keep their own npm installs.
- Tests: `pnpm test` runs Vitest (`vitest.config.ts`): the legacy tests in `test/` through `test/support/node-test.mjs` (the node:test API on Vitest, until each module converts and its test moves next to it as `*.test.ts`), the tools' tests, the service worker's tests (`app/src/sw/*.test.ts`, on the worker exactly as published) and the Worker's tests inside the Workers runtime (`workers/vitest.config.ts`, `@cloudflare/vitest-plugin`). About a minute. `pnpm typecheck` type checks every package.
- Lint: `pnpm lint` runs ESLint (`eslint.config.js`: typescript-eslint strict on every TypeScript file; in `app/src` React, the React hooks and Compiler rules, `react/no-danger` and no `innerHTML`, `outerHTML` or `insertAdjacentHTML`; `lvm/server-safe` in route modules and components, which refuses `window`, `document`, `localStorage`, `sessionStorage` and `Date.now()` where a server render reaches them (a component's render, a custom hook's body, and the callbacks a render runs at once; effects, handlers, `typeof` and functions inside `<ClientOnly>`'s children are allowed); the legacy `js/` files only for `lvm/legacy-imports`, the import rule in `CODING_STANDARDS.md`, which `build.py` also fails on) and stylelint (`stylelint.config.js`: no hex, `rgb()`, `rgba()`, `hsl()` or `hsla()` colors in `app/src/**/*.css`). The local rules are in `tools/eslint-rules/`, each with a fixture in `tools/eslint-rules/fixtures/` that `tools/test/lint-rules.test.ts` checks fails as expected. `eslint .` reads every `.js` file it is not told to ignore, so its `ignores` list names build output (`_*/**`), `vendor/`, `e2e/`, `cloud/`, `deploy/`, `test/`, `site/`, `moved/`, `theme/`, `docs/`, `openspec/`, the voice and brand tools and the rule fixtures; stylelint runs on `app/src/**/*.css` only. A build in a folder not starting with `_` is linted (its vendored Firebase copy fails), which is why `build.py` refuses one.
- Budgets (performance-budget spec): every build but `--dev` prints the first-load table from `tools/budget.ts` (the Brotli size of everything a first visit to `/play/` requests before the first tap: the page, what it loads, the entry's static imports, `sw.js` and every file in `PRECACHE`) and fails above `firstLoad.total` in `docs/perf/baseline.json`, naming the largest new or grown file. Under the table it prints the before-play lines (openspec change `render-performance`, design D2, task 2.1 on the Legacy game): the JS the game page itself requests before the first tap (its scripts and the static module graph of `/js/app.js`), its CSS, and the JS of the largest landing or grown-up page, each against the owner's budget in `budgets` of `baseline.json` (150 KB, 40 KB and 15 KB Brotli; `--json` writes them under `beforePlay`); a budget whose `failing` flag is on fails the build when over, naming the budget, the size and the largest file or the page; one the start measurement missed (JS before play, about 306 KB, and the landing page's JS, about 21 KB, on 2026-11-01) prints as missed until a pull request meets it and turns `failing` on in the same commit (D2 item 4). The ratchet (task 2.3): a build more than 64 bytes under `firstLoad.total`, or a reported budget now met, prints the line to record in `baseline.json`. The baseline names its voice mode (`firstLoad.voice`, `off` today); a build in another mode prints the table without failing until that mode has a baseline. A pull request that grows first load on purpose updates the baseline and says why; the new number comes from `node tools/budget.ts _site --json <file>`. The preview's `perf` job runs `e2e/perf/lighthouse.mts` and `e2e/perf/interactions.ts` against the preview and against production in the same job, page by page on one runner, and `tools/perf-compare.ts --production` counts each limit from production's median of that job, the regression the pull request adds (total blocking time +25 ms, layout shift above the larger of production's and 0.1, interactions +20 ms; largest contentful paint +100 ms over the baseline, as before, with production shown, since the hosts differ on the network chain; the baseline is shown for information; first contentful paint is reported with its 100 ms limit but not gated until the server-rendered shell, openspec change `perf-gate-fcp` and react-typescript 2.7; both hosts' CPU speed, Lighthouse's `benchmarkIndex`, is printed under the table; openspec change `perf-same-runner`, `docs/perf/baseline.md`, "The same-runner reference"), posting the table on the pull request; the job is advisory (owner, 2026-10-31): a miss posts a warning, measured once, and never fails the pull request; the Lighthouse simulation's server latency is fixed (`serverResponseTime` in `tools/lighthouserc.json`), so the preview host's own answer time does not count (`docs/perf/baseline.md`, "The server latency is fixed"); on `main` after a deploy the same run measures production beside the pinned reference build (`reference.commit` in `baseline.json`, built and uploaded at the preview alias `perf-ref` by `e2e.yml`'s `reference` job, the one job there holding the preview token) and counts the same limits from the reference (`--reference`, `--reference-label`, `--label`), opening an issue on a second miss instead of failing; when the reference could not be uploaded it compares with the baseline alone and says so under the table (`--reference-missing`); `perf_only` runs it by hand (openspec change `perf-gate-same-runner-post-deploy`, `docs/perf/baseline.md`, "The post-deploy reference"). The pin moves only with a reason. `docs/perf/baseline.md` says how the baseline was measured.
- Pre-commit hook in `.githooks/pre-commit` runs `pnpm typecheck`, `pnpm lint` and `pnpm test` (`node --test` is gone: `test/support/node-test.mjs` gives the old tests the node:test API on Vitest), then builds into a throwaway directory outside the repo (`mktemp -d`; catches build errors and committed stamps). The same four commands are the checklist in `.github/pull_request_template.md`, the Checks tables in the README and `CONTRIBUTING.md`, and "Checks before a push" in `AGENTS.md`; change them together.
- `.github/workflows/ci.yml`: `pnpm install --frozen-lockfile`, the type check, lint, the tests, the build and its checks, `compose.py --check`, a wrangler dry run of both Workers, and `tools/check-workflow-secrets.mjs` (each deploy credential named only by its own job) on every push and pull request, and beside it the `scan` job (Semgrep Community Edition with the JavaScript, Python and GitHub Actions rulesets, and gitleaks over the whole history, merge commits included, with the allow-list in `.gitleaks.toml`, printing each finding without its line; design D12, so scanning goes on once the repo is private and CodeQL stops). On `main` only, once the owner's setup is done: `voice-upload` (R2) then `deploy` (`wrangler deploy` of the ledger Worker, then of the main Worker that binds it, with the token from the `production` environment). `preview.yml` uploads a preview version per same-repo pull request and runs the suite against it. `moved.yml` publishes the Phase B moved page to GitHub Pages, by hand.
- A new repo-only file or folder goes in `exclude` in `_config.yml`; a new repo-only root file also goes in the repo-only loop in `.github/workflows/ci.yml` and, for a root doc, the lists in `test/build.test.mjs`.
- The main-branch ruleset requires one approving review, resolved review threads and the `check` job. GitHub Actions in the workflows are pinned by commit SHA with a version comment; keep them that way.
