# Build, checks and hook

Detail behind the rules in `CLAUDE.md`. Read this before touching `build.py`, `sw.js`, `_config.yml`, the hook or the CI workflow.

- Never commit cache stamps. In git, `index.html` has no import map and loads plain `/vedic-math/js/app.js` and `/vedic-math/math.css`, and `sw.js` keeps `const VERSION = 'dev';` and `const PRECACHE = [];` between the precache markers. The CI `check` job runs `python3 build.py --out _site` and uploads the result as the Pages artifact; the `deploy` job publishes that artifact. The build copies the publishable files and stamps the copies (the import map pinning every module to `?v=<hash>`, the entry script and `math.css`, the worker's `VERSION` and precache list, the `#vm-css` map for the play stylesheets, and the Content-Security-Policy meta tag), so there is nothing to run after editing. The build fails if the source carries stamps.
- The published files are every file git knows about minus `exclude` in `_config.yml` and any path with a part starting with `.` or `_`; the build also writes `.nojekyll`.
- Tests: `node --test 'test/**/*.test.{js,mjs}'` (about three minutes; the slow suites are the cloud and clip-hash tests).
- Pre-commit hook in `.githooks/pre-commit` builds into a throwaway directory (catches build errors and committed stamps) and runs the tests. Enable once per clone: `git config core.hooksPath .githooks`.
- `.github/workflows/ci.yml` runs the tests and the build on pushes and pull requests to `main`, runs the Firestore rules tests against the emulator (`cloud/test`), and checks that `_site/` is stamped and holds no repo-only files. Its `deploy` job publishes that `_site/` with actions/deploy-pages only when the repository variable `PAGES_VIA_ACTIONS` is `true` and Settings > Pages > Source is "GitHub Actions". Without both, Pages deploys `main` with Jekyll, which publishes the unstamped source: it works, but nothing is pinned and the `'dev'` worker means no offline. The live site is stamped today (check: the page loads `app.js?v=<hash>` and carries an import map).
- Repo-only files are listed in `exclude` in `_config.yml` (`cloud/`, `test/`, `docs/`, `tools/`, `e2e/`, `CLAUDE.md`, the README, `build.py`). Add new ones there. `docs/agent/` is covered by `docs/`.
- The main-branch ruleset requires one approving review, resolved review threads and the `check` job. GitHub Actions in the workflows are pinned by commit SHA with a version comment; keep them that way.
