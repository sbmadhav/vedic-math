# Build, checks and hook

Detail behind the rules in `AGENTS.md`.

- Hosting (ADR 0004): Cloudflare Workers static assets (`wrangler.jsonc`), deployed by CI from `main`. Until the move's owner setup is done, the old app at https://sbmadhav.com/vedic-math/ keeps serving from this repo's GitHub Pages; `--target moved` builds its Phase B replacement (Targets).
- Stamps (the cache stamps rule is in `AGENTS.md`; the worker's `VERSION` and `PRECACHE` sit between the precache markers). `python3 build.py --out _site` copies the publishable files and stamps the copies: the import map pinning every module to `?v=<hash>`, `?v=` on every same-origin script and stylesheet of every page, the `#vm-css` map for the play stylesheets, the worker's `VERSION` and precache list. The worker is published as `/sw.js` from `app/src/sw/sw.ts` with its types taken out by `tools/build-sw.mjs` (Node's own type stripper, so the build needs Node 22.13 or newer and no install; every line keeps its place, so the marker lines publish exactly as before). The build fails if the source carries stamps.
- Pages: `play/index.html` (the game) and every `site/**/*.html` (landing, grown-up pages, `404.html`, later `/import/`). Each holds the header from `theme/header.html` (`docs/agent/design-system.md`). `<!-- include-md: PATH -->` renders a Markdown file into a page (the legal pages, `/licenses/` from `THIRD-PARTY-NOTICES.md`), without its title, its drafting note or any section headed "(remove before publishing)".
- `_headers` (written by the build): the security headers on `/*`; per page path a `Content-Security-Policy` (that page's inline script hashes plus `THIRD_PARTIES`), a stricter `Content-Security-Policy-Report-Only` and COOP, so no page carries a policy `<meta>`. Never put a policy or COOP on `/*`: Cloudflare joins every matching rule, and two policies are both enforced. The build fails on more than 100 rules or a line over 2,000 characters (then move an inline script out of the page).
- `THIRD_PARTIES` in `build.py` is the one list of outside hosts a page or worker may reach, with why and when; `LINKS` lists hosts that are only linked or cited. The build fails on any other host in a published file (vendored files and licence texts aside), on any `/vedic-math/` path outside `_redirects`, on any sbmadhav.com reference other than the export page, and on `gstatic.com/firebasejs`.
- Vendored files: `vendor/design-system/2.1.0/`, `vendor/firebase/<v>/` (`tools/vendor-firebase.mjs`), `vendor/goatcounter/` each have a `SHA256SUMS` the build and `test/vendor.test.mjs` check. Every file under `vendor/` or `fonts/` needs an entry in `THIRD-PARTY-NOTICES.md`. The published `/ds/2.1.0/tokens.css` drops its `@font-face` lines; `theme/fonts.css` declares the fonts once.
- Targets: `--dev` (no stamps, `'dev'` worker, into `_dev/`), `--preview` (adds `X-Robots-Tag: noindex, nofollow`), `--target moved` (the Phase B page for sbmadhav.com/vedic-math/, into `_moved/`: `moved/index.html` as `index.html` and `404.html`, the packer and schema pinned, `sw.js` with `KILL = true` and the old `vedic-math-` prefix), `--voice static` (Workers Paid file limit), `--voice off` (no Studio voice: the voice host is left out of the policy and `sw.js`, the published `js/voice-index.js` names no recording, and the build fails if any published file names the voice host; CI builds this way while `vars.R2_ACCOUNT_ID` is empty). `BUILD_TODAY=YYYY-MM-DD` fakes the date for the security.txt expiry check. `--out DIR` puts the build anywhere outside the repo, or inside it only when its first path part below the repo root starts with `_` (`_site`, `_check/site`; `build/_site` is refused because `build` does not; the default outputs do; a worktree build is `--out _<name>`): git and ESLint ignore `_*/` (`.gitignore`, `eslint.config.js`), the build never publishes a path starting with `_`, and `build.py` refuses the repo itself and any other place inside it (`test/build.test.mjs` checks both).
- Limits (Cloudflare Workers Free): 20,000 files, 25 MiB a file; `/.well-known/security.txt` must expire more than 30 days ahead and less than a year ahead.
- The published files are every file git knows about minus `exclude` in `_config.yml` and any path with a part starting with `.` or `_` (so thumbnails are `thumbs/yt-<id>.webp`). The build also writes `_redirects`, `robots.txt`, `sitemap.xml`, `.well-known/security.txt` and `.assetsignore`.
- Workspaces (openspec change react-typescript, phase 1): pnpm, pinned by `packageManager` in `package.json` (`corepack enable`, then `pnpm install`), with the packages `app/` (the service worker source today; the React Router app from phase 2), `shared/`, `workers/` (the Worker: `src/index.ts` routes `/_csp` to `src/csp.ts`), `e2e/` and `tools/`. `tsconfig.base.json` holds the strict settings every package extends. `tools/voice`, `tools/sutra-voice`, `cloud/test` and `deploy/` keep their own npm installs.
- Tests: `pnpm test` runs Vitest (`vitest.config.ts`): the legacy tests in `test/` through `test/support/node-test.mjs` (the node:test API on Vitest, until each module converts and its test moves next to it as `*.test.ts`), the tools' tests, the service worker's tests (`app/src/sw/*.test.ts`, on the worker exactly as published) and the Worker's tests inside the Workers runtime (`workers/vitest.config.ts`, `@cloudflare/vitest-plugin`). About a minute. `pnpm typecheck` type checks every package.
- Lint: `pnpm lint` runs ESLint (`eslint.config.js`: typescript-eslint strict on every TypeScript file; in `app/src` React, the React hooks and Compiler rules, `react/no-danger` and no `innerHTML`, `outerHTML` or `insertAdjacentHTML`; `lvm/server-safe` in route modules and components, which refuses `window`, `document`, `localStorage`, `sessionStorage` and `Date.now()` where a server render reaches them (a component's render, a custom hook's body, and the callbacks a render runs at once; effects, handlers, `typeof` and functions inside `<ClientOnly>`'s children are allowed); the legacy `js/` files only for `lvm/legacy-imports`, the import rule in `AGENTS.md`, which `build.py` also fails on) and stylelint (`stylelint.config.js`: no hex, `rgb()`, `rgba()`, `hsl()` or `hsla()` colors in `app/src/**/*.css`). The local rules are in `tools/eslint-rules/`, each with a fixture in `tools/eslint-rules/fixtures/` that `tools/test/lint-rules.test.ts` checks fails as expected. `eslint .` reads every `.js` file it is not told to ignore, so its `ignores` list names build output (`_*/**`), `vendor/`, `e2e/`, `cloud/`, `deploy/`, `test/`, `site/`, `moved/`, `theme/`, `docs/`, `openspec/`, the voice and brand tools and the rule fixtures; stylelint runs on `app/src/**/*.css` only. A build in a folder not starting with `_` is linted (its vendored Firebase copy fails), which is why `build.py` refuses one.
- Budgets (performance-budget spec): every build but `--dev` prints the first-load table from `tools/budget.ts` (the Brotli size of everything a first visit to `/play/` requests before the first tap: the page, what it loads, the entry's static imports, `sw.js` and every file in `PRECACHE`) and fails above `firstLoad.total` in `docs/perf/baseline.json`, naming the largest new or grown file. The baseline names its voice mode (`firstLoad.voice`, `off` today); a build in another mode prints the table without failing until that mode has a baseline. A pull request that grows first load on purpose updates the baseline and says why; the new number comes from `node tools/budget.ts _site --json <file>`. The preview's `perf` job runs `e2e/perf/lighthouse.mts` and `e2e/perf/interactions.ts` against the preview and against production in the same job, page by page on one runner, and `tools/perf-compare.ts --production` counts each limit from production's median of that job, the regression the pull request adds (total blocking time +25 ms, layout shift above the larger of production's and 0.1, interactions +20 ms; largest contentful paint +100 ms over the baseline, as before, with production shown, since the hosts differ on the network chain; the baseline is shown for information; first contentful paint is reported with its 100 ms limit but not gated until the server-rendered shell, openspec change `perf-gate-fcp` and react-typescript 2.7; both hosts' CPU speed, Lighthouse's `benchmarkIndex`, is printed under the table; openspec change `perf-same-runner`, `docs/perf/baseline.md`, "The same-runner reference"), posting the table on the pull request; a miss re-measures only the kind that missed, on both hosts; the Lighthouse simulation's server latency is fixed (`serverResponseTime` in `tools/lighthouserc.json`), so the preview host's own answer time does not count (`docs/perf/baseline.md`, "The server latency is fixed"); on `main` the same run against production alone, compared with the baseline, opens an issue instead (`e2e.yml`). `docs/perf/baseline.md` says how the baseline was measured.
- Pre-commit hook in `.githooks/pre-commit` runs `pnpm typecheck`, `pnpm lint` and `pnpm test` (`node --test` is gone: `test/support/node-test.mjs` gives the old tests the node:test API on Vitest), then builds into a throwaway directory outside the repo (`mktemp -d`; catches build errors and committed stamps). The same four commands are the checklist in `.github/pull_request_template.md`, the Checks tables in the README and `CONTRIBUTING.md`, and "Checks before a push" in `AGENTS.md`; change them together.
- `.github/workflows/ci.yml`: `pnpm install --frozen-lockfile`, the type check, lint, the tests, the build and its checks, `compose.py --check`, a wrangler dry run, and `tools/check-workflow-secrets.mjs` (each deploy credential named only by its own job) on every push and pull request. On `main` only, once the owner's setup is done: `voice-upload` (R2) then `deploy` (`wrangler deploy` with the token from the `production` environment). `preview.yml` uploads a preview version per same-repo pull request and runs the suite against it. `moved.yml` publishes the Phase B moved page to GitHub Pages, by hand.
- A new repo-only file or folder goes in `exclude` in `_config.yml`; a new repo-only root file also goes in the repo-only loop in `.github/workflows/ci.yml` and, for a root doc, the lists in `test/build.test.mjs`.
- The main-branch ruleset requires one approving review, resolved review threads and the `check` job. GitHub Actions in the workflows are pinned by commit SHA with a version comment; keep them that way.
