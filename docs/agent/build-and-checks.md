# Build, checks and hook

Detail behind the rules in `CLAUDE.md`. Read this before touching `build.py`, `sw.js`, `_config.yml`, `wrangler.jsonc`, the hook or the CI workflows.

- Never commit cache stamps. In git, `play/index.html` has no import map and loads plain `/js/app.js` and `/math.css`, and `sw.js` keeps `const VERSION = 'dev';` and `const PRECACHE = [];` between the precache markers. `python3 build.py --out _site` copies the publishable files and stamps the copies: the import map pinning every module to `?v=<hash>`, `?v=` on every same-origin script and stylesheet of every page, the `#vm-css` map for the play stylesheets, the worker's `VERSION` and precache list. The build fails if the source carries stamps.
- Pages: `play/index.html` (the game) and every `site/**/*.html` (landing, grown-up pages, `404.html`, later `/import/`). Each holds the header from `theme/header.html` exactly as the vendored `compose.py` writes it; after editing the partial run `python3 vendor/design-system/2.1.0/compose.py theme/header.html <page>` for each page (the build and CI fail on a stale header). `<!-- include-md: PATH -->` renders a Markdown file into a page (the legal pages, `/licenses/` from `THIRD-PARTY-NOTICES.md`), without its title, its drafting note or any section headed "(remove before publishing)".
- `_headers` (written by the build): the security headers on `/*`; per page path a `Content-Security-Policy` (that page's inline script hashes plus `THIRD_PARTIES`), a stricter `Content-Security-Policy-Report-Only` and COOP. Never put a policy or COOP on `/*`: Cloudflare joins every matching rule, and two policies are both enforced. No page carries a policy `<meta>`. The build fails on more than 100 rules or a line over 2,000 characters (then move an inline script out of the page).
- `THIRD_PARTIES` in `build.py` is the one list of outside hosts a page or worker may reach, with why and when; `LINKS` lists hosts that are only linked or cited. The build fails on any other host in a published file (vendored files and licence texts aside), on any `/vedic-math/` path outside `_redirects`, on any sbmadhav.com reference other than the export page, and on `gstatic.com/firebasejs`.
- Vendored files: `vendor/design-system/2.1.0/`, `vendor/firebase/<v>/` (`tools/vendor-firebase.mjs`), `vendor/goatcounter/` each have a `SHA256SUMS` the build and `test/vendor.test.mjs` check. Every file under `vendor/` or `fonts/` needs an entry in `THIRD-PARTY-NOTICES.md`. The published `/ds/2.1.0/tokens.css` drops its `@font-face` lines; `theme/fonts.css` declares the fonts once.
- Targets: `--dev` (no stamps, `'dev'` worker, into `_dev/`), `--preview` (adds `X-Robots-Tag: noindex, nofollow`), `--target moved` (the Phase B page for sbmadhav.com/vedic-math/, into `_moved/`: `moved/index.html` as `index.html` and `404.html`, the packer and schema pinned, `sw.js` with `KILL = true` and the old `vedic-math-` prefix), `--voice static` (Workers Paid file limit), `--voice off` (no Studio voice: the voice host is left out of the policy and `sw.js`, the published `js/voice-index.js` names no recording, and the build fails if any published file names the voice host; CI builds this way while `vars.R2_ACCOUNT_ID` is empty). `BUILD_TODAY=YYYY-MM-DD` fakes the date for the security.txt expiry check.
- Limits (Cloudflare Workers Free): 20,000 files, 25 MiB a file; `/.well-known/security.txt` must expire more than 30 days ahead and less than a year ahead.
- The published files are every file git knows about minus `exclude` in `_config.yml` and any path with a part starting with `.` or `_` (so thumbnails are `thumbs/yt-<id>.webp`). The build also writes `_redirects`, `robots.txt`, `sitemap.xml`, `.well-known/security.txt` and `.assetsignore`.
- Tests: `node --test 'test/**/*.test.{js,mjs}'` (about three minutes; the slow suites are the build, cloud and clip-hash tests).
- Pre-commit hook in `.githooks/pre-commit` builds into a throwaway directory (catches build errors and committed stamps) and runs the tests. Enable once per clone: `git config core.hooksPath .githooks`.
- `.github/workflows/ci.yml`: tests, the build and its checks, `compose.py --check`, a wrangler dry run, and `tools/check-workflow-secrets.mjs` (each deploy credential named only by its own job) on every push and pull request. On `main` only, once the owner's setup is done: `voice-upload` (R2) then `deploy` (`wrangler deploy` with the token from the `production` environment). `preview.yml` uploads a preview version per same-repo pull request and runs the suite against it. `moved.yml` publishes the Phase B moved page to GitHub Pages, by hand.
- Repo-only files are listed in `exclude` in `_config.yml` (`cloud/`, `test/`, `docs/`, `tools/`, `e2e/`, `site/`, `moved/`, `worker/`, `deploy/`, `wrangler.jsonc`, `CLAUDE.md`, the README, `build.py`). Add new ones there.
- The main-branch ruleset requires one approving review, resolved review threads and the `check` job. GitHub Actions in the workflows are pinned by commit SHA with a version comment; keep them that way.
