# End-to-end tests (`e2e/`)

Detail behind the testing guardrail in `AGENTS.md` and the Tests rule in `CODING_STANDARDS.md`.

- The local server (`node e2e/local-server.mjs 8124 _site`, "Checks before a push" in `AGENTS.md`) serves the build the way Cloudflare does, with `_headers`, `_redirects`, trailing slashes and the 404 page; serve `_dev` for a build without stamps, or run `npx wrangler dev` from `deploy/` for Cloudflare's own runtime. Pages are at `/` (landing) and `/play/` (the game, `APP` in `fixtures.ts`); modules at `/js/`. The game's screens are paths under `APP` (`/play/arena`, `/play/skills`; openspec change `indexable-routes`, `js/paths.js`): `open(page, '#/arena')` loads the page with that fragment, which the router turns into its path before the view draws, and `open(page, '/play/arena')` loads the path cold; a spec expects an address with `atRoute('#/arena')`, a drawn link with `hrefTo('#/arena')` or `pathTo('#/arena')`, never a literal `/play/` or `#/` form, so the move to `/learn/` changes `APP` alone. Until the prerendered pages exist (task 2.3), the local server answers a path under the game's folder with the game's shell.
- Before the voice host (`https://voice.learnvedicmath.com/`) is live, set `E2E_VOICE_ORIGIN` to another copy of the voice files (for example `https://sbmadhav.com/vedic-math/voice` until Phase B); the fixtures answer the voice host from there. Without it, specs that read aloud see the host fail to resolve. A targeted run (`--project=chromium tests/<spec>.spec.ts`, or `-g "<test name>"`) is the normal loop; the full three-project suite is for the final check before a push.
- The suite targets the LIVE https://learnvedicmath.com/ by default (projects chromium, webkit, mobile). First run, after the install in `AGENTS.md`: `cd e2e && pnpm exec playwright install chromium webkit`.
- `e2e/tests/fixtures.ts` replaces the Firebase SDK with a fake that records attempted writes (`cloudLog(page)`), and aborts and fails the test on any write-shaped request to `firestore.googleapis.com`. Only `leaderboard.live.spec.ts` loads the real SDK (reads only, no sign-in and no Auth SDK, chromium, no retries).
- The service worker is blocked (`serviceWorkers: 'block'` in `e2e/playwright.config.ts`) everywhere except `e2e/tests/offline.spec.ts`. Playwright WebKit does not route requests from a worker-controlled page, so the fake SDK and the local analytics answer are bypassed there (real anonymous sign-ins, counted visits), and a controlled page would test the worker's cache instead of what the network serves. Keep offline specs off WebKit and keep their tripwire for live Google backends.
- Analytics never counts a test run: `fixtures.ts` answers GoatCounter (`/vendor/goatcounter/count.js` and its endpoint) and Cloudflare Web Analytics locally, and specs that check events replace `/js/analytics.js` with a stub that records `window.siteTrack` calls.
- Third parties: `tests/third-party.spec.ts` reads `THIRD_PARTIES` from `build.py` (the checkout's copy) and fails a first visit on any request to a host not on it, or to any Google or YouTube host. The video player opens on a facade (this site's thumbnail behind `.vp-play`); a spec that needs the YouTube frame presses it first, and routes YouTube to an empty page as `tests/watch.spec.ts` does.
- Known axe violations go in `KNOWN` in `e2e/tests/a11y.spec.ts` (each becomes a `test.fixme` with a note); remove the entry when fixed.
- `e2e/tests/cov/` holds one spec per live OpenSpec scenario, named `<spec>-<n>.spec.ts`, with a comment naming the requirement and scenario. In CI they run on chromium only, and the run after a push or on a preview leaves them out (`E2E_SKIP_COV=1`), so the run stays inside the job timeout. Locally every project runs them. Archiving an OpenSpec change adds the coverage specs for the scenarios it makes live.
- The pages are sent with a Content-Security-Policy header without `'unsafe-eval'` (`policyOf()` in `fixtures.ts` reads it): never build a function from a string inside `page.evaluate` (`new Function`, `eval`); pass a named option and keep the code in the page function. A stricter Report-Only policy reports `style=""` and Trusted Types; violation watchers ignore events whose `disposition` is `report`.
- `.github/workflows/e2e.yml` runs the suite daily (06:23 UTC), on demand (optional `base_url`) and on pushes to `main` (after its `deploy` job waits for the Cloudflare deploy), in six shards on six runners (`--shard=i/6`, every project in each, in the `mcr.microsoft.com/playwright` image of the version `e2e/package.json` pins, so no browser install; one job took 28 to 29 minutes after a push and 43 to 46 daily, past its 50-minute limit); a failed shard's blob report is merged into one `playwright-report` artifact by the `report` job, and a newer push cancels the run for an older one; `preview.yml` runs it against each pull request's preview (chromium). The daily and manual runs also check every Watch shelf video on YouTube (`tests/videos.live.spec.ts`, tagged `@live-videos`) on a runner of its own (the `videos` job, `--workers=4`; the shards leave it out, since under their load an embed could miss its 10 s wait), and, by the repository variable `MOVE_PHASE`, the moved page (B) or the 301 from sbmadhav.com/vedic-math/ (C).
- World boards: a spec about the World board starts with `await needsWorldBoards(page)` (fixtures), which skips it while the served `js/cloud-config.js` has `FIREBASE = null` (the device-only launch, until task 8.5); `boards-off.spec.ts` covers that state and skips once a config is served.
- A spec reaches the game's own modules through `e2eMod('<name>')` inside `page.evaluate` (for `/js/<name>.js`: `'store'`, `'play/kit'`), and `mod(page, '<name>')` from Node when it needs the URL; never `import('/js/...')`. Both come from `fixtures.ts` and read the build's module map (`/learn/assets/modules.json`, published only by preview and test builds once the framework build bundles the modules; the identity until then), so specs keep working when module URLs change (openspec change react-typescript, design D10). A spec that makes its own context with `browser.newContext` calls `installModules(ctx, baseURL)` there.
- A spec that holds a module in flight (a `page.route` that waits before it continues) opens the page with `page.goto(url, { waitUntil: 'domcontentloaded' })` and then waits for the view, not with `open()`: WebKit holds the load event for an import started before it, so `open()` (which waits for load) times out there while the route is held (`load.spec.ts`, `sutras-first.spec.ts`).
- Fake browser APIs (speech, camera) are installed with `page.addInitScript` before `open()`; the verses specs are the pattern for a fake `speechSynthesis`.
- Under a faked clock, end a timed round with `page.clock.fastForward(61_000)`: the round's next animation frame reads the time and ends it. `runFor` fires every timer on the way, about 3,800 animation frames for a 60-second round, which on a busy machine took about 30 s of real time per round and ran tests past their budget. Keep `runFor` for timers that must each fire (a countdown, the weekly Sparks post's wait). Install a clock a little before the time you pause at: an installed clock runs, so `pauseAt` the install time is already in the past.
- A fake device must behave like the real one in the way the app relies on: the fake camera is already sending frames when `getUserMedia` resolves (a canvas stream handed over before its first frame was now and then never loaded by Linux WebKit), and a test that is not about idle scheduling can make `requestIdleCallback` answer at once (a busy browser gives idle callbacks only at their timeout).
- `tests/background-perf.spec.ts` (tag `@frame-cost`) times the sky's draw per frame with the CPU slowed 4x, and its first frame on the Deep dive, where it measures a page of 2,000 elements. In CI it runs on a runner of its own (the `frame-cost` job in `e2e.yml`, in the same Playwright image as the shards; after the suite, with its own `--output` and `PLAYWRIGHT_HTML_OUTPUT_DIR`, in `preview.yml`; `--grep @frame-cost --workers=1` in both), and the suite leaves it out (`--grep-invert`): with three workers on a four-core runner the other browsers preempt the timed frame, and its p95 read 3.6 to 6.6 ms for frames of about 1 ms (p50; 0.2 ms on a laptop), failing every run since the sky landed. The budget (2 ms, twice that on CI) is unchanged; a slower drawing still fails. Keep a new timing spec under the same tag.
