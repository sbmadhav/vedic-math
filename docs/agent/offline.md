# Offline

`app/src/sw/sw.ts` is the game's service worker, published at `/sw.js` with its types taken out (`tools/build-sw.mjs`, see `build-and-checks.md`) and registered by `js/app.js` with scope `/learn/` (on https and localhost; openspec change `indexable-routes` task 2.2 moved the game from `/play/`, and task 2.4 adds the retiring branch for a worker still registered under `/play/`). Its tests (`app/src/sw/*.test.ts`) run the published form; `/api/` requests are never answered by it. The landing and grown-up pages are never controlled.

- `build.py` writes its `VERSION`, `PRECACHE` list and `LAZY` list into the published copy (between the `build.py: precache` markers). `PRECACHE` is the core (openspec change `render-performance`, design D10, owner P5): the shell `/learn/` (`learn/index.html`; the route pages under `/learn/` are never precached), every file it loads (stamped scripts and styles, the design system, the theme), every module of the core at its import-map URL (the static import graph of `js/app.js` and the late modules its routes load), the body and heading fonts, the icons and the manifest. Every entry has a hash the worker checks on install; a mismatch fails the install and the previous version keeps serving. `LAZY` names the stamped URLs the install leaves out (`is_lazy()` in `build.py`: the Play experiences `js/play/exp/`, their styles `css/play/`, `js/play/life.js` and the video list `js/videos.js`); the build fails if one of them is in the static import graph. The two fonts only the experiences use (Space Grotesk, JetBrains Mono) and the landing page's `js/landing-sky.js` are in neither list. A `'dev'` worker has no fetch handler (network only) and deletes `lvm-*` caches. To test the real worker, build `_site` and serve it (`python3 build.py && node e2e/local-server.mjs 8124 _site`).
- Page loads in `/learn/` are network first with the saved shell as the offline fallback (every route page is the shell with its own head, so the saved shell draws any path offline), through the browser's navigation preload (design D11: `activate` enables it, `page()` takes `event.preloadResponse` before fetching); `?v=` files are cache first, and a miss is saved when the response is a success of the type its name promises (a module is JavaScript, a stylesheet CSS; never the 404 page), so an experience opened once online opens offline; other same-origin files network first. Other origins (Firebase, Google, YouTube, analytics) and non-GET requests are never cached. Leaderboards fall back to this device when offline. Offline, a shelf card for an experience the worker never saved says "Needs a connection the first time" (`js/play/offline-note.js`, loaded only offline; it asks the worker `{ type: 'cached?', urls }` on a `MessageChannel` port), and opening one shows the Retry message (a reload at the same route).
- Caches are `lvm-<VERSION>`; the worker keeps the current and previous one, and never deletes `lvm-voice` or `lvm-sounds`. On activate it copies the saved `LAZY` files it still uses from the caches before it (the same stamped URL is the same bytes), so a deploy that does not change an experience keeps it offline; saved stamped files are never trimmed with the `RUNTIME_MAX` plain-URL entries.
- New same-origin files the game loads must be referenced by `learn/index.html`, `theme/fonts.css` or the manifest (build.py lists them), and a module worker is started with `new Worker(new URL('./x.js', import.meta.url), { type: 'module' })`, the form a bundler recognizes (phase 2 of openspec change react-typescript). Until then that URL has no `?v=` stamp, so the worker file is network first like other plain files.
- To retire it, set `KILL` to `true` in `app/src/sw/sw.ts` and deploy (see the comment there). `build.py --target moved` ships the same file with `KILL = true` and the old prefix `vedic-math-` to retire the old sbmadhav.com worker in Phase B.
- `manifest.webmanifest` makes the game an installable app ("Learn Vedic Math", `id` `/play/`, which never changes since it names the installed app, scope `/learn/`, start `/learn/?source=pwa`, shortcuts as paths, any and maskable icons at 192 and 512 in `/icons/`, the Arena, Practice and Sutras shortcuts, and screenshots in `/screenshots/` for the richer install dialog; openspec change `install-app`). Every manifest icon is precached; the screenshots are not (only the browser's install dialog reads them). Remake the screenshots with `e2e/screenshots.mjs` after a visible change to Home or a Star, and the icons with `tools/brand/render.mjs`.
- Installing (`js/install.js`, its pure rules in `js/install-rules.js`): the Install guide, the Install nudge on Home and the Prompt slot (`js/prompt-slot.js`). In the Installed app, links outside `/learn/` get `target="_blank"` so they open in the browser, and the brand goes to `#/`. The nudge's schedule is `vm.install` on this device. Specs simulate the browser's offer with a synthetic `beforeinstallprompt` and the Installed app with an init script (`e2e/tests/install-helpers.ts`).
- `sounds/` (the 29 Sutra name clips in `sounds/sutras/` and the Om) is served cache first from `lvm-sounds`, a cache every deploy keeps, and is never precached. The clips are made by `tools/sutra-voice/make-sutra-clips.mjs`, which also writes `js/say-clips.js` (each clip's size and `?v=` content hash); remake both together (`test/say.test.mjs` checks them).
- The Studio voice (`https://voice.learnvedicmath.com/`, `docs/agent/studio-voice.md`) is served cache first from `lvm-voice` (CORS responses from that host are cached), a cache every deploy keeps, and is never precached.
- `vendor/tesseract/` (the Math Lens digit reader, about 11 MB) and `vendor/firebase/` are fetched on first use and never precached.
