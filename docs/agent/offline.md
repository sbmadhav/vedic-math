# Offline

`app/src/sw/sw.ts` is the game's service worker, published at `/sw.js` with its types taken out (`tools/build-sw.mjs`, see `build-and-checks.md`) and registered by `js/app.js` with scope `/play/` (on https and localhost). Its tests (`app/src/sw/*.test.ts`) run the published form; `/api/` requests are never answered by it. The landing and grown-up pages are never controlled.

- `build.py` writes its `VERSION` and `PRECACHE` list into the published copy (between the `build.py: precache` markers): the shell `/play/`, every file it loads (stamped scripts and styles, the design system, the theme), every module at its import-map URL, the play stylesheets, the fonts, the icons and the manifest. Every entry has a hash the worker checks on install; a mismatch fails the install and the previous version keeps serving. In git that block stays `'dev'` and empty; never stamp it by hand. A `'dev'` worker has no fetch handler (network only) and deletes `lvm-*` caches. To test the real worker, build `_site` and serve it (`python3 build.py && node e2e/local-server.mjs 8124 _site`).
- Page loads in `/play/` are network first with the saved shell as the offline fallback; `?v=` files are cache first; other same-origin files network first. Other origins (Firebase, Google, YouTube, analytics) and non-GET requests are never cached. Leaderboards fall back to this device when offline.
- Caches are `lvm-<VERSION>`; the worker keeps the current and previous one, and never deletes `lvm-voice` or `lvm-sounds`.
- New same-origin files the game loads must be referenced by `play/index.html`, `theme/fonts.css` or the manifest (build.py lists them), and a module worker is started with `new Worker(new URL('./x.js', import.meta.url), { type: 'module' })`, the form a bundler recognizes (phase 2 of openspec change react-typescript). Until then that URL has no `?v=` stamp, so the worker file is network first like other plain files.
- To retire it, set `KILL` to `true` in `app/src/sw/sw.ts` and deploy (see the comment there). `build.py --target moved` ships the same file with `KILL = true` and the old prefix `vedic-math-` to retire the old sbmadhav.com worker in Phase B.
- `manifest.webmanifest` makes the game an installable app ("Learn Vedic Math", `id` and scope `/play/`, start `/play/?source=pwa`, icons in `/icons/`).
- `sounds/` (the 29 Sutra name clips in `sounds/sutras/` and the Om) is served cache first from `lvm-sounds`, a cache every deploy keeps, and is never precached. The clips are made by `tools/sutra-voice/make-sutra-clips.mjs`, which also writes `js/say-clips.js` (each clip's size and `?v=` content hash); remake both together (`test/say.test.mjs` checks them).
- The Studio voice (`https://voice.learnvedicmath.com/`, `docs/agent/studio-voice.md`) is served cache first from `lvm-voice` (CORS responses from that host are cached), a cache every deploy keeps, and is never precached.
- `vendor/tesseract/` (the Math Lens digit reader, about 11 MB) and `vendor/firebase/` are fetched on first use and never precached.
