Prerequisite: the owner has listened to `docs/prototypes/voice/` on a phone and a laptop, approved this change, and confirmed the open decisions in `design.md` (the Explorer clip voice, Heart for Challenger and Pro, 32 kbps, committing the packs to git, the 99% floor). Part A (tasks 1) can ship on its own before part B.

## 1. Tune the built-in voice (A)

- [ ] 1.1 `js/voice.js`: `rateVoice(v)` returns `{ tier: 'good' | 'ok' | 'poor', pts }` from the name and `voiceURI` (rules in design decision 2); `englishVoices()` sorts by it; `bestVoice()` never returns a poor voice when a good or ok one exists; a voice picked by name in Me still wins. Verify: new `test/voice.test.mjs` with fake voice lists: macOS Safari (`com.apple.voice.compact.en-US.Samantha` and `com.apple.voice.enhanced.en-US.Ava`) picks Ava; Windows Edge (`Microsoft David - English (United States)` and `Microsoft Aria Online (Natural) - English (United States)`) picks Aria; Chrome on macOS picks `Google US English` over `Samantha`; Android (`English United States`, no vendor) is ok; a list of only `Albert`, `Zarvox` and `eSpeak` returns the best poor voice; non-English voices are never returned.
- [ ] 1.1b Child voices: Microsoft Ana and Maisie online voices are rated good with `kid: true`; for Explorer, best available ranks them first, for Challenger and Pro after every other good voice. Verify: `test/voice.test.mjs` with an Edge voice list (Ana, Aria, Jenny, Maisie, David): Explorer gets Ana, Pro gets Aria; a list without a child voice gives Explorer the same voice as Pro.
- [ ] 1.2 `speakBuiltIn()`: pitch 1 always; rate 0.9 for Explorer, 0.95 otherwise; the 140 ms breath between sentences stays. Verify: `test/voice.test.mjs` stubs `speechSynthesis` and `SpeechSynthesisUtterance` and asserts pitch 1 and rate 0.9 with `body.mode-explorer`, 0.95 without; Playwright `e2e/tests/voice.spec.ts` "built-in voice is tuned": with an init script that records every `speechSynthesis.speak()` utterance, an Explorer Practice question is spoken with pitch 1 and rate 0.9.
- [ ] 1.3 Me settings: the picker lists good and ok voices first and marks poor ones "(robotic)"; when every English voice is poor, the poor-voice note shows (copy in design decision 3, no em dashes) with "Got it", stored per Player as `vm.voiceNoteSeen`. Verify: `voice.spec.ts` "poor-voice note": an init script makes `speechSynthesis.getVoices()` return only compact voices; `#/me` shows the note with the iPhone and Windows steps; after "Got it" and a reload it is gone; with an Enhanced voice in the list it never shows. `e2e/tests/a11y.spec.ts` `#/me` still has no new violations, and the 320px accessibility scenario still holds with the note shown.

## 3. Clip voice (B, app)

- [ ] 3.1 `js/voice.js`: `planLine(words)` (from `stitch-plan.mjs`, moved into `js/`) turns a normalized line into clip ids; `speakClips(plan, my)` loads the packs it needs (decoded once per visit with `decodeAudioData`, found by searching for sound around each clip's start) and schedules them on one `AudioContext` with a 40 ms gap, 120 ms for a comma and 260 ms for a sentence end, 6 ms fades. `speak()` follows the voice order in the spec. Verify: `test/voice.test.mjs`: plans for "7 plus 5 equals what?", "Count up from 9 to 16. First get to 10." (16 uses the end take), "4368 divided by 16 equals what?" (four thousand, three hundred, sixty eight), a negative and a decimal; a line with an unknown frame returns `null`.
- [ ] 3.2 Pack loading: `js/voice-clips.js` is imported only when read aloud first plays; the core pack loads on `requestIdleCallback` (or after 2 s) once read aloud is on; other packs on first need; a line whose pack is not ready is read by the built-in voice. Every timer and listener goes through `js/life.js` where it belongs to a view. Verify: `voice.spec.ts` "no packs when read aloud is off" (Challenger Practice round, no request to `/vedic-math/voice/`); "Explorer core pack": an Explorer Practice question after the pack loads plays clips (a test hook `window.__voiceLog` records `clips` or `builtin` per line) and `speechSynthesis.speak` is not called; "first line falls back": with the pack request held, the first line is `builtin` and a later one `clips`; `test/lifecycle-scan.test.mjs` still passes.
- [ ] 3.3 `stop()` stops scheduled clip sources and bumps the token so a pack that finishes loading late never plays a stale line; iOS: set `navigator.audioSession.type = 'playback'` where it exists so the ringer switch does not silence clips. Verify: `voice.spec.ts` "leaving stops clips": start a clip line, go to `#/learn`, and `__voiceLog` shows no clip started after the route change; `e2e/tests/games.spec.ts` balloon stop and start test still passes; the owner checks on a real iPhone with the ringer off that clips play (note the result in the PR).
- [ ] 3.3b Clip lines pick the pack by Mode: Explorer lines from the core pack in the Explorer clip voice; Challenger and Pro lines from Heart packs (which hold their own number clips). Verify: `test/voice.test.mjs` plans an Explorer "7 plus 5 equals what?" against the core pack and a Pro "45 times 53 equals what?" against the Heart number clips; `voice.spec.ts` "Explorer hears the kid voice": Explorer praise logs `clips:kid`, a Challenger Practice question with read aloud on logs `clips:heart`.
