# Proposal

Status: approved for implementation by the owner 2026-10-19 (task 0.0), and revised with the owner's decisions N1 to N8 of 2026-10-20 (all "yes"): server-side rendering with React Router v7 framework mode on Cloudflare Workers, a hybrid voice with a server endpoint, and the follow-on Duels and Live sessions on Durable Objects. The `learnvedicmath` move is live (its Phase A), so the start condition is met; archiving that change is still pending and its open tasks do not block this one (task 0.1). The owner answered Q18 to Q26 on 2026-10-19, and the four questions the 2026-10-20 decisions raised (Q27 to Q30) on PR #100 the same day, "yes" to each default: anonymous Worker-signed tickets for Players with no Firebase identity, no grown-up override for under-13 Duel results, a $5 a day and $150 a month voice cap, and Workers Paid before phase 2 reaches production.

## Why

The game is about 40 hand-written ES modules (about 9,800 lines in `js/`, 10,800 with data) with no framework and no bundler. Views draw themselves by assigning template strings to `innerHTML`: `js/app.js` alone does it 69 times, `js/games.js` 22, `js/arena.js` 15, `js/star.js` 10. Every one of those is a place where a value that is not escaped by hand (`esc()`) becomes markup, so cross-site scripting is a class of bug the code invites rather than one it rules out. `js/app.js` is 1,497 lines holding the router, every view and every dialog, and each new feature (Play, verses, the Sky, Star Quest) has added to it. Lifecycle safety depends on every author remembering `js/life.js`, enforced after the fact by a regex scan (`test/lifecycle-scan.test.mjs`) with an allow-list of exceptions.

The owner wants three things (decision 1): **safety** (no `innerHTML` XSS class), **maintainability**, and **speed of building features**. The plans that follow the move (`placement`, `age-bands`, `duel-online`, `render-performance`, `gpu-effects`, and the Live sessions the owner asked for on 2026-10-20) would each add more template-string views, more hand-written listeners and, in `gpu-effects`, a hand-written WebGL engine. The owner decided (2026-10-17: decisions 1 to 4 and 6 to 13; 2026-10-19: decision 5, path URLs, Q18) to move the game to React 19 and TypeScript first, step by step, and to build those plans in React afterwards.

On 2026-10-20 the owner widened the stack (N1 to N8). The game will have real server code (online Duels, Live sessions, a voice endpoint), so it stays on Cloudflare with TypeScript Workers, Durable Objects and R2 (N1), and the React app is rendered on the server by React Router v7 in framework mode inside the same Worker, instead of a Vite single-page app (N2). Read aloud becomes hybrid (N3): fixed words stay pre-recorded, and sentences with a question's own numbers are voiced once by the server, cached in R2 and capped by a daily spend limit, so Explorer Players hear the studio voice for nearly every line instead of stitched clips or the device's voice.

Player speed is not the goal of this change; it stays the job of `render-performance`, re-planned for React. This change must not make the game slower: first load and interaction time are measured in CI against a baseline of today's site and may not regress (decision 1).

## What Changes

- **Stack (decision 4, revised by N1 and N2).** React 19 with the React Compiler, TypeScript `strict`, and React Router v7 in **framework mode with server-side rendering in a Cloudflare Worker** (the Cloudflare Vite plugin), replacing the Vite single-page app and React Router SPA mode. Static files (hashed assets, prerendered pages, landing pages) are served first by Workers static assets and never run code; the Worker renders only the game routes that have no prerendered page. No Vercel, no Next.js (the design compares Next.js with the OpenNext adapter and says why it was rejected).
- **Step by step (decision 2).** No big-bang rewrite. The router mounts either a Legacy view (today's template-string view, run through an adapter with its `{ signal }`) or a React view per route. Each pull request moves a few views and the Playwright suite stays green after every one. Order (N7): phase 1 is framework-neutral tooling (workspaces, TypeScript, tests, lint, the typed service worker), phase 2 is the React Router framework-mode shell on Workers serving the Legacy views, then the logic in TypeScript, the shell pieces, and the views from simplest to most interactive, with games, Arena, Party Mode and Play last.
- **Logic stays framework-free (decision 6).** Game, math and storage logic become plain TypeScript modules with no behavior change. React reads them through one small `useStore(selector)` hook on `useSyncExternalStore`. No Redux or Zustand. Player data never reaches the server: it stays on the device, so server rendering draws only what does not depend on it.
- **Path URLs in the game (decision 5, revised by N2).** `/play/` uses path routes (`/play/arena`, `/play/sutras/ekadhikena`) from phase 2. A game path with no prerendered page is rendered by the server; there is no SPA fallback file. A tiny pre-paint shim turns every `#/...` into its path, forever. The Sutra pages, the Guide and the first-visit Mode picker stay prerendered at build time (Q20), because they are the same for every visitor and then cost no Worker run.
- **Content security policy (N2).** Server-rendered pages allow their inline scripts with a fresh nonce per request, set by the Worker; prerendered pages keep hashes in `_headers`. Everything else in the policy is unchanged and comes from one source for both.
- **Styling (decision 7).** Plain CSS with design-system tokens; `math.css` is split into one CSS file per component. No Tailwind, no CSS-in-JS. Both color schemes. The design system is v2.1, consumed as the move vendors it.
- **Markup (Q19).** Content HTML strings (question text, Trick steps, pictures) render only through one allow-list `Markup` component; `dangerouslySetInnerHTML` is banned everywhere else.
- **Lifecycle (decision 8).** `js/life.js` retires when the last Legacy view goes. React views clean up through `useEffect` and a `useAbortSignal()` hook. The lifecycle scan becomes an ESLint rule that bans bare `addEventListener`, `setTimeout` and `requestAnimationFrame` in components.
- **Service worker (decision 9, revised by N2).** Stays hand-written, as `sw.ts`, with today's caching rules as the move leaves them. Its precache list comes from the client build's manifest. The offline shell is a page the build renders, so offline page loads under `/play/*` still open the game. No Workbox.
- **Testing (decision 10, with N8).** Playwright stays the behavior contract and keeps asserting the same behavior (selectors and URL forms may change). E2E specs stop addressing internal modules by `/js/<x>.js` URLs: one helper in `e2e/tests/fixtures.ts` maps them to the built module (about 87 spec files change their pattern, never their assertions). Vitest replaces `node --test`. React Testing Library only for tricky components.
- **One repo, three workspaces (decision 11).** pnpm workspaces: `app/` (React Router app), `workers/` (the one Worker: the CSP report endpoint, the server render handler, the voice endpoint, and later the Duel and Live session Durable Objects) and `shared/` (question generators, scoring, message types and the voice sentence rules, used by both).
- **Hybrid voice (N3, new capability `server-voice`).** Fixed text (explanations, Sutra names, lessons, praise) stays pre-recorded with Google Chirp 3 HD Aoede and served from R2. Sentences that hold a question's own numbers go to a Worker endpoint that asks Google Text-to-Speech once per unique normalized sentence and keeps the audio in R2 under a hash of the text and voice. A daily spend cap is enforced on the server: $5 a day and $150 a month (Q29), with the recording tool's month budget lowered to $150, so both stay inside the owner's $300 a month; the $50 per run guard stays. The device voice is the fallback whenever the cap is hit, the network is down or the line is slow. The Google key lives only in a Cloudflare secret; only the sentence text is sent, and only sentences the game itself can say are accepted, so no personal data can be in them. Built in its own phase after phase 2.
- **Server access (N6, Q27).** Firebase anonymous auth and World boards stay. Server code verifies a Firebase ID token before room or voice access when the Player has one; a Player with none (every under-13 Player, and anyone who never posted) gets a short-lived anonymous ticket the Worker signs. No identity is ever created.
- **Superseded rules.** React and TypeScript supersede "no framework, no bundler, no TypeScript in the browser" in the `learnvedicmath` design, `openspec/config.yaml`, ADR 0010 and `render-performance`; ADR 0012 supersedes those parts. Server rendering supersedes ADR 0012's first form (SPA mode, "no request-time rendering") and the "site stays static assets" consequence of ADR 0004 for `/play/` routes without a prerendered page.
- **Feature work keeps going (decisions 3 and 12).** Feature pull requests pause only for the views being moved; each migration pull request names the views it locks. Content work (videos, voice, verses) continues throughout. Star Quest's mobile layout is redone when its view moves, and the owner signs it off from phone screenshots on its PR (Q24).
- **3D with Three.js (decision 13).** Unchanged by server rendering: React Three Fiber and drei, bundled from our own origin, load late and only in the browser (scenes never render on the server). A CI budget keeps the whole 3D dependency graph under 170 KB Brotli; 3D files are never precached; Calm, Pause motion and reduced motion get a still frame; no WebGL or under 30 frames a second for 3 seconds gets the 2D drawing; 3D renders on the main thread and pauses in a hidden tab. The Sky ships in this change as the first 3D scene.

## Out of scope

- New features, new copy or new game rules. A moved view looks and behaves as before, except Star Quest's mobile layout (decision 3), the URL form (Q18), the 3D Sky (Q23) and the server voice (N3), which changes which voice says a line, never what is said.
- Player speed work beyond "no regression": minifying targets, prefetching, Speculation Rules, font subsetting stay in `render-performance`, re-planned for React and server rendering.
- Placement, age bands, online Duels (`duel-online`, kept by the owner, Q26, re-planned onto this stack, N4) and Live sessions (N5): built after this change, in React, from their own changes. Live sessions is a new change to be proposed after Duels; it is not created here.
- The 3D scenes after the Sky (Sutra deep-dive illustrations, game effects, Mandala art): the revised `gpu-effects`.
- The landing and grown-up pages (`site/`): they stay the static pages the move builds. Only `/play/` becomes a React app.
- Server loaders and actions that read or write Player data. The server renders content and the app shell only; Player data stays on the device.
- Vercel, Next.js, OpenNext, Redux, Zustand, Tailwind, CSS-in-JS, Workbox.
- Changing what is stored on the device. Storage keys and formats stay exactly as they are, so no Player needs a migration.
- Changing what is sent, except the server voice: Boards, analytics events and their names, and Firebase usage stay as they are. The server voice adds one thing that is sent (the text of a game sentence, with no Player data), so `parentNote()`, `cloud/README.md` and the privacy drafts change in the server voice phase (task group 11), not before.

## Modes and Players affected

Every Mode (Explorer, Challenger, Pro) and every Player, but nothing a Player does changes:
- Every Player sees path URLs in `/play/` once the shell moves (Q18). Bookmarks, shared links, home-screen apps and Hand-off links with `#/...` keep opening the same screen.
- Players on phones get a redone Star Quest layout when the Star round moves.
- Players with a WebGL device and motion allowed see the Sky fade into 3D in the 3D phase. Players with Calm, Pause motion or reduced motion see a still frame. Players without WebGL, or on a device that stays under 30 frames a second for 3 seconds, keep today's 2D Sky.
- Players with read aloud on (every Explorer by default, any Challenger or Pro who turns it on) hear the studio voice say lines with their question's own numbers once the server voice ships, and the device's voice when the daily cap is reached or they are offline. Players under 13 get the same voice through an anonymous ticket (Q27); nothing their device sends says anything about them, and no identity is created.
- Nothing new is kept about any Player. `parentNote()` and `cloud/README.md` change only to describe the server voice.

## Capabilities

### New Capabilities

- `app-routing`: path routes under `/play/`, one router mounting a Legacy view or a React view per route, the hash shim for old links, server rendering of game routes, prerendered Sutra pages, Guide and first-visit Mode picker, no Player data on the server, focus and scroll on route change.
- `app-build`: the pnpm workspaces, React Router framework mode on the Cloudflare Vite plugin, TypeScript `strict`, hashed client output, lint rules for lifecycle and markup safety, the per-request nonce and hash policy, Vitest, and what CI and the pre-commit hook check.
- `scenes-3d`: where 3D may be used, how it loads (browser only), the fallbacks (still frame, 2D, paused), its byte budget and its tests.
- `performance-budget`: the baseline from today's site, measured before phase 2, and the CI gates on the client manifest, the server-rendered document and the Worker bundle that stop first load and interaction time from regressing. `render-performance`, re-planned, later tightens it.
- `server-voice`: fixed words from recordings, game sentences voiced once by the server and cached in R2, the accepted sentences, the daily spend cap, the device-voice fallback, access checks, and what is sent.

### Modified Capabilities

- `hosting` (added by `learnvedicmath`): the game's paths, static files first, the Worker rendering game routes that have no file, the 404 rules, and how old links reach the same screen.
- `offline-app` (added by `learnvedicmath`): the precache list comes from the client build's manifest and never holds a 3D file; the offline shell is a page the build renders; hashed asset files are cache first (3D files once first loaded); offline page loads under `/play/*` get the shell.
- `deploy-pipeline` (added by `learnvedicmath`): the post-deploy wait checks the built entry and the Worker's build id instead of `/js/app.js`, and the budget gates run.
- `analytics`: route views are counted for path routes, with the same event names.
- `view-lifecycle`: cleanup holds across Legacy and React views, and is enforced by lint.
- `page-layout`: Star Quest fits a phone.
- `read-aloud` (added by `better-voice`): the voice order gains the Server line between a whole recording and the clips. `better-voice` is archived before this change, so `openspec validate --strict` shows an "Archive would refuse" notice for it until then.

ADRs: `docs/adr/0012-react-and-typescript-for-the-game.md` (revised 2026-10-20 for server rendering with React Router v7 framework mode on Workers), `docs/adr/0013-three-js-for-3d-decoration.md` (unchanged; noted that 3D stays browser-only), and new `docs/adr/0014-server-side-voice-synthesis-with-an-r2-cache.md`. ADR 0012 supersedes the "no framework, no bundler, no TypeScript in the browser" parts of ADR 0010; ADR 0013 supersedes ADR 0011's "no library", 20 KB budget and OffscreenCanvas worker; ADR 0014 supersedes `better-voice`'s "the game calls no speech provider" guardrail (the browser still calls none; the server does, capped).

## Order

1. The `learnvedicmath` move: live (Phase A). Its archive is pending and does not block.
2. This change. Its baseline (task 0.4) is measured on the live site before phase 2.
3. Then, in React and in this order (owner, 2026-10-19, with N5 of 2026-10-20): `placement`, `age-bands`, `render-performance`, `duel-online`, Live sessions (a new change, on the same Durable Object room engine as Duels), `gpu-effects`, each re-planned with `/opsx:update` (or proposed, for Live sessions) before it is built (task group 12).
